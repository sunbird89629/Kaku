# Kaku Remote 手机键盘布局方案

## 问题

手机软键盘弹出时，可见区域变小。此前网页随之缩小终端区域，并向 Mac 发送新的终端行列数；Codex 等终端应用收到尺寸变化后重新排版，键盘开合过程中可能出现画面跳动和重复绘制。

## 方案

采用类似 Android 窗口平移的体验：键盘弹出期间保持终端网格和字号不变，根据浏览器可见视口的变化向上平移页面，使终端底部和快捷键栏位于键盘上方。键盘收起后页面恢复原位。

- 保留键盘弹出前的页面高度和安全区，避免终端区域因键盘或安全区变化而改变尺寸。
- 键盘开合不发送终端 resize；点击终端时避免重复声明相同的行列数。
- 横屏时快捷键栏覆盖在页面上，避免它出现时挤压终端区域。
- 横竖屏切换等实际窗口尺寸变化仍重新计算布局。Mac 接管终端尺寸或页面重新获得焦点时，网页仍可重新声明尺寸。

键盘打开时，终端上方的一部分内容会暂时移出可见区域。网页通过 `visualViewport` 实现这一行为，并不依赖 Android 原生窗口设置。

## 高度、安全区与键盘识别

页面初始化时记录 `visualViewport.height`，将该高度写入 `body.style.height`；键盘弹出后仍使用这个高度。页面还读取当时计算出的 `padding-bottom` 并固定为像素值，避免输入法改变系统底部安全区时挤压终端。画面位置单独通过 `transform: translateY(...)` 调整，键盘收起时清除平移。

浏览器没有直接提供通用的键盘开关状态，页面使用以下条件判断键盘弹出：

1. 输入框、文本域或可编辑元素获得焦点。
2. `visualViewport.scale === 1`，即页面没有缩放。
3. 可见视口高度比记录的页面高度减少超过 40 CSS 像素。

进入键盘状态后，只要可见高度仍比记录高度小超过 1 像素，就保持该状态，避免动画末尾反复切换。可见视口宽度改变超过 1 像素时，页面将其视为新布局，重新记录宽度、高度和安全区，以支持旋转等变化。

这是启发式判断：输入焦点存在时，地址栏、分屏或其他系统界面导致的高度变化可能被误判为键盘；高度减少不超过 40 像素的键盘可能无法识别。浏览器和设备之间的行为差异需要实测。

## 验证状态

- 在连接的 Android 手机、Chrome 和真实输入法上，使用隔离的模拟终端连续开合键盘五次：终端保持 50 列、38 行，终端容器高度不变，未发送 resize。
- 手机截图显示终端底部输入区和快捷键栏位于键盘上方。
- 网页自动化测试 131 项通过，覆盖模拟键盘开合、横屏布局和终端尺寸恢复。
- 尚未验证真实 Codex 会话、真实手机横屏和 iOS；上述测试不代表这些场景已通过。该改动尚未部署。
